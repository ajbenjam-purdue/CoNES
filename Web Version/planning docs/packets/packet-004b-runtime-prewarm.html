Runtime Prewarm

Packet 004B moves runtime loading out of the Run click path. The app should begin preparing the CoNES Worker as soon as the browser app loads, then show runtime readiness in Tools before the user selects a file.

Human accepted Runtime ready before file selection Optimistic runtime After Packet 004 No solver refactor No backend

Goal

User Experience

Opening the app starts runtime preparation. By the time the user inspects Tools or selects a file, the Worker should report Runtime ready. Clicking Run should go straight to solve work rather than visibly loading WASM and runtime-data.

Runtime Shape

A shared browser Worker accepts a prewarm message, loads cnes-module.js and cnes-module.wasm, verifies and mounts /runtime-data, then stays alive for subsequent run messages.

Preserved Contract

The solve contract is unchanged

Runtime prewarm does not change CoNES input or output. Runs still write the selected file to /work/input.cnes and call callMain(["/work/input.cnes", "--json"]) with thisProgram: "/app/cnes". 

App load
  -> shared CoNESWorkerClient
  -> worker.postMessage({ type: "prewarm" })
  -> load WASM and mount runtime-data
  -> Tools shows Runtime ready
  -> Run writes input and calls CoNES

Implementation Results

Shared Worker

The client now keeps a shared Worker alive instead of creating and terminating one Worker per run. A prewarmed runtime is reused by Runner and Tools.

Prewarm Status

runtime-prewarm.ts tracks idle, preparing, ready, and failed states. Runner and Tools subscribe to the same readiness state.

Verification

Browser verification waits for data-runtime-prewarm-state="ready" before running solve cases, then checks that Tools shows runtime readiness. Local verification passed with npm run verify:runtime-metadata, npm run verify:runtime-data, npm run build, and npm run verify:browser.

Done Criteria

  • App load starts Worker prewarm automatically.
  • Tools reports Runtime ready before file selection after prewarm completes.
  • Runner reuses the warmed Worker for Run.
  • Browser verification waits for prewarm before solve cases.
  • Human acceptance confirms the perceived Run delay is no longer dominated by runtime asset loading.

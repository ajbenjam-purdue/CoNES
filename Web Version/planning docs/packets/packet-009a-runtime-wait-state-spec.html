Packet 009A Spec Sheet

Runtime Wait State

Replace inert runtime-loading language with a compact rotating operations status while the browser worker prepares the validated CoNES runtime. The wait should feel directional without exposing debug tooling or changing solver behavior.

Implemented locally Workbench only No worker contract change No CoNES core change No deploy setting change

Intent

Problem

The current pre-run state reads like passive loading. It does not reassure the user that the browser runtime is doing useful setup work before Run and Lint become available.

Decision

Use a rotating list of operational startup messages in the Workbench header while the worker is preparing. The copy should sound like an IDE boot sequence, not a marketing explanation.

Modification Scope

Modify

WorkbenchPage.tsx may add local UI state for the rotating wait message and replace the visible prewarmState.label in the runtime gate.

Do Not Modify

Do not change runtime-prewarm.ts, worker-client.ts, worker-contract.ts, cnes-worker.js, runtime manifests, CLI flags, CoNES C++ source, or Vercel settings.

Visible Copy

Avoid public copy such as Loading assets. Prefer operation-oriented labels like starting the worker, mounting runtime files, indexing materials, linking libraries, checking JSON output, and unlocking the Workbench.

Failure State

If the runtime fails, stop rotating and show the actual runtime failure label/message. Optimism must not hide real errors.

Acceptance

  • Before runtime readiness, Workbench actions remain hidden.
  • The runtime gate rotates through multiple operation labels.
  • Once ready, normal New/Open/Save/Lint/Run actions appear.
  • No worker payloads, runtime files, or solver contracts change.

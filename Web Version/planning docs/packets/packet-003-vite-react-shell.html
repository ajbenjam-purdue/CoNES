Packet 003

Vite React App Shell

This packet turns the accepted Packet 002 browser runner into the foundation of the real Web Version app. The stack is Vite, React, TypeScript, Tailwind CSS v4, and shadcn/ui, deployed as static assets to Vercel with all solver execution remaining in the client browser.

Scaffold Pass Result

Implemented

The Web Version now has a Vite, React, TypeScript, Tailwind CSS v4, and shadcn-compatible source component scaffold. The application opens to a React Runner screen and includes thin navigation lanes for Runner, CLI, Linter, Tools, and Docs.

Verified

npm run build, npm run verify:runtime-data, and the Chrome browser smoke matrix passed against the React app at http://127.0.0.1:4173/runner/.

Human Accepted

The React runner was manually verified after the scaffold commit. Selecting a .cnes file from the Vite app works as intended and preserves the accepted browser runtime behavior from Packet 002.

Runtime Contract Preserved

The React shell still calls /runtime/cnes-worker.js. The worker continues to use thisProgram: "/app/cnes", mounts assets from /runtime-data, and invokes callMain(["/work/input.cnes", "--json"]).

Component Status

npx shadcn@latest info --json recognizes the project as Vite, Tailwind v4, Radix base, and lucide. Packet 003 currently uses local source-owned shadcn-style primitives for buttons, badges, alerts, tabs, scroll area, tooltip, and separator.

Goal

User Outcome

A user lands on a real app shell instead of a proof page. The first screen is still the runner, but the layout can grow into Runner, CLI, Linter, Tools, and Docs sections without moving away from client-side execution.

Engineering Outcome

The accepted Worker and WASM assets remain stable while UI code moves into React components. Local development, static build, runtime-data verification, and browser runner verification become package scripts.

Stack Contract

Area Use Notes
Framework Vite React TypeScript Use a static SPA build. Do not introduce Next.js or server-only conventions.
Styling Tailwind CSS v4 Theme tokens belong in the Tailwind global CSS file generated for the Vite app.
Component system shadcn/ui Use source-owned shadcn components before custom controls: Sidebar, Tabs, Button, Badge, Alert, Table, ScrollArea, Resizable, Tooltip, Dialog, Command.
Icons lucide-react unless shadcn project context says otherwise Use icons in buttons and tool controls; avoid text-only controls where a familiar icon exists.
Validation zod for worker messages and manifest-facing data Keep runtime contracts explicit without changing CoNES JSON output.
Editor candidate Monaco in a later packet Do not add the editor in Packet 003 unless the shell migration is already passing cleanly.

2. Runtime Preservation

Do not break Packet 002
  • Keep public/runtime and public/runtime-data static paths stable.
  • Keep worker invocation at callMain(["/work/input.cnes", "--json"]).

3. Runner Migration

React components
  • Move the existing file input, run/reset controls, status, stdout, stderr, and download behavior into React components.
  • Preserve raw stdout JSON as source of truth; parsed views are secondary.
  • Use shadcn components for controls, panels, alerts, tabs, badges, tooltips, and resizable output areas.

4. App Navigation

Thin shell
  • Add top-level sections for Runner, CLI, Linter, Tools, and Docs.
  • Only Runner needs full behavior in Packet 003; other sections can be empty states with clear ownership.
  • Do not make a marketing landing page; the application should open to the usable runner.

Carry forward

  • Run runtime-data verification against the packaged manifests.
  • Run Chrome browser verification against the Vite dev server or preview server.

Packet 009 Spec Sheet

Product Shell And Naming

This packet defines the next product pass before implementation. The goal is to turn the current working IDE into a named, focused operating web app without exposing internal planning, runtime tooling, or fake project-management concepts.

Naming Decision

Recommended Product Name

Use CoNES Studio as the public app name. It is specific enough to be branded, broad enough for IDE behavior, and does not imply a backend service, cloud workspace, or multi-file project system that does not exist yet.

Surface Name

Keep Workbench as the name of the main editing surface. The app is CoNES Studio; the primary screen is the Workbench.

Names To Retire From Public UI

Retire Web Version, Runner, Workspace, Tools, and Browser Workspace from the default product surface. These are implementation or planning terms.

Fallback Names

CoNES Lab is acceptable if the product should feel more experimental. CoNES IDE is clear but less polished. The default recommendation remains CoNES Studio.

Product Shape

Public App

The public app is a local-first browser IDE for one active .cnes source buffer. It should open directly to the editing, linting, running, and results experience.

Truthful File Model

The app supports one active source buffer: create a draft, open a .cnes file, edit it, save/download it, rename it, lint it, run it, and export JSON. This is not project file management yet.

Not Yet A Project Workspace

Do not show file explorer, project, workspace, folder, package, or include-path language until multiple files, browser project persistence, and include resolution are real.

Operating Principle

The product should make CoNES easier to author and inspect without hiding the validated computational engine or pretending the browser has capabilities it does not have.

Ticket 009A: Rename Active Buffer

Decision

Add lightweight filename editing for the one active buffer. This is not file management; it only names the current source before Save, Run, Lint, and JSON export.

Interaction

The filename in the Workbench header becomes editable. Click the filename to edit, press Enter to commit, press Escape to cancel, and blur should commit if the value is valid.

Validation

Reject empty names. If the user omits the extension, append .cnes. Keep the input compact and avoid a modal or file-management drawer.

Propagation

The renamed filename drives the header, .cnes download name, JSON download basename, and worker fileName metadata. Opening a file still adopts the uploaded filename. New draft resets to untitled.cnes.

Ticket 009B: Default Dark Mode

Decision

Make the product default to dark mode. CoNES Studio should feel like an IDE by default, and Monaco already uses a dark editor theme.

No Public Theme Toggle Yet

Do not add a visible theme switch in this pass. Theme control can come later if users ask for it. This ticket only establishes the default product presentation.

Implementation Target

Update global design tokens and app surfaces so the Workbench, Results, Diagnostics, buttons, borders, and empty states read as one coherent dark IDE. Avoid heavy gradients, decorative effects, or one-note purple/blue treatment.

Verification

Check desktop and mobile widths for contrast, button readability, Monaco framing, Results legibility, Diagnostics severity states, and runtime-ready gate visibility.

Controls

Visible Controls

After runtime readiness, show only New, Open, Save, Lint, Run, and JSON, plus inline filename editing. These map to the active buffer and result export.

Runtime Gate

Before the Web Worker is ready, hide operational buttons and show a compact runtime loading state. Do not show disabled controls that imply the user can act before the runtime is usable.

File Management Boundary

Open means import one local .cnes file into the active buffer. Save means download that buffer. Neither should imply a managed project, folder, or cloud workspace.

Noise Rule

Remove or hide explanatory copy that describes how the website works. The user should be able to operate from labels, state, and familiar IDE controls.

Debug Surfaces

Hard-Coded Flag

Keep a hard-coded debug flag, currently showDebugSurfaces = false. Do not add a public toggle until there is a clear user-facing need for it.

Hidden By Default

Hide Workspace, Tools, Docs, raw stdout/stderr, raw lint output, runtime metadata, worker contract text, and runtime timing internals when debug is off.

Available For Development

When the flag is enabled, internal routes and raw output can return for debugging, verification, and agent review. The flag is for development posture, not a public product feature.

Verification Update

Browser verification must understand both product mode and debug mode. Product mode should not fail because internal tooling is hidden.

Guardrails

Approval received

This spec sheet was the checkpoint before code. The current implementation pass should now be reviewed against the approved CoNES Studio, one-buffer, and dark IDE direction.

No fake workspace

Do not call the product a workspace or project manager until it supports real project behavior.

Keep the engine stable

Preserve ["/work/input.cnes", "--json"] for Run and ["/work/input.cnes", "--lint", "--json"] for Lint.

Human review target

The review question is whether CoNES Studio, one-buffer honesty, and hidden debug surfaces match the desired product direction.

Acceptance Criteria

  • Public product name is approved or replaced.
  • Default UI opens as a focused IDE, not a dashboard or planning surface.
  • Workspace, Tools, Docs, raw output, and runtime internals remain hidden unless debug is enabled.
  • Open and Save describe one active .cnes buffer, not project file management.
  • The active filename can be renamed inline and propagates to Save, JSON export, and worker file metadata.
  • The default product theme is dark, coherent with Monaco, and readable on desktop and mobile.
  • Runtime-ready gate remains in place before operational controls appear.
  • Run, Lint, Results, Diagnostics, and JSON export continue to work.
  • No CoNES C++ core, WASM artifact, runtime manifest, or worker contract changes are introduced.

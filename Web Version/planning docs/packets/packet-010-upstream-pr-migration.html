Packet 010 Spec Sheet

Upstream Pull Request Migration

Move CoNES Studio from the standalone web deployment repository into the original CoNES repository as an additive browser workbench, then point Vercel at the corrected upstream source after the pull request is accepted.

Approved for execution Fork based Additive PR No C++ core rewrite Client-only runtime

Source Repositories

Upstream

The authoritative project is ajbenjam-purdue/CoNES. The pull request branch must be based on its default branch so GitHub can review the web app as a normal addition.

Current Web Repo

Rmorr2001/cones-web-version remains the staging source for the web app until the upstream pull request is accepted. Its unrelated history should not be merged directly into upstream.

PR Scope

Include

Include Web Version/, packaged runtime assets under Web Version/public/runtime*, and the current planning docs so the browser workbench context travels with the implementation.

Exclude

Exclude .vercel/, dist/, node_modules/, root-level Vercel link files, and unrelated local agent instructions.

Preserve

Preserve .cnes, --json, --lint, runtime-data manifests, raw solver output, and the validated C++ solver core.

Do Not Change

Do not refactor CoNES/src/main.cpp, move solver contracts, add a backend solve API, or make Vercel the source of runtime truth.

Vercel Redirect

After upstream acceptance, change the Vercel project Git source from Rmorr2001/cones-web-version to ajbenjam-purdue/CoNES while keeping Web Version as the root directory, Vite as the framework, npm install as install command, npm run build as build command, and dist as output directory.

Acceptance

  • Pull request branch is based on ajbenjam-purdue/CoNES.
  • PR includes only the browser workbench contribution and supporting docs.
  • Local web verification passes from inside Web Version.
  • PR description states that the C++ solver core and CLI contracts are preserved.
  • Vercel source-repo swap waits until the PR is accepted.

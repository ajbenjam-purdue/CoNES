Packet 008A

Manual Lint Diagnostics

Packet 008A adds a deliberate Lint action to the Monaco Workbench. The goal is to prove the diagnostic contract before automatic linting starts running while the user types.

Implemented locally Manual first Line-level markers Monaco markers Browser smoke added No C++ refactor Client-only

Position

Opinionated Decision

Lint starts as a button, not as a background process. A user asks for diagnostics when ready, and the app proves the worker mode, diagnostic shape, Monaco marker behavior, and failure UI before any debounce loop exists.

User Outcome

From the Workbench, a user can edit .cnes, click Lint, and see diagnostics near the editor without running a solve.

Review Finding

Native Probe Result

Local native probes show --lint --json returns a stable JSON envelope. Valid lint exits 0 with success: true. Invalid lint exits 1 with success: false and parser errors such as [Line 2].

Marker Precision

Current CoNES lint output gives line data, not column data. Packet 008A should ship line-level Monaco markers only. Column precision is a future diagnostic-format improvement, not a blocker.

Scope

Object Modify Do Not Modify
worker-contract.ts Add an explicit lint request/result shape if the current worker needs one. Do not alter existing solve result semantics or WorkerRunResult for solve.
worker-client.ts Add lintSource, parallel to runSource. Do not change runSource, runArgv, or solve behavior.
cnes-worker.js Add a type: "lint" message mode that invokes --lint --json. Do not change WASM loading, runtime-data mounting, thisProgram, or solve invocation.
WorkbenchPage.tsx Add a Lint action, lint status, and diagnostics panel/state. Do not make lint block Run, Save, Monaco editing, or raw output preservation.
MonacoSourceEditor.tsx Accept diagnostic marker input and apply Monaco markers. Do not add completion, language server behavior, or semantic analysis.

Runtime Contract

Solve Stays Fixed

Solve still uses the existing argument vector. Do not mutate runArgv or infer CLI arguments from UI state. 

const runArgv = ["/work/input.cnes", "--json"] as const;

Lint Gets Its Own Path

Lint uses a separate worker/client path with an internal constant. The UI should not pass arbitrary argv. 

const lintArgv = ["/work/input.cnes", "--lint", "--json"] as const;

Client API

Add a dedicated method so Workbench can lint the current Monaco buffer without pretending lint is a solve. 

client.lintSource({
  fileName,
  contents,
  lastModified,
});

Result Handling

The raw lint response may reuse the existing runtime result envelope, but UI diagnostics should be normalized in a separate adapter before reaching Monaco markers.

Diagnostic Contract

Normalize First

Normalize from parsed JSON error first, then fall back to stderr or raw text. Extract line numbers from messages like [Line 2]. Do not invent column data.

Raw Text Remains

Raw lint stdout/stderr must remain inspectable under Raw output. The normalized diagnostics panel is a view, not a replacement for the CLI output. 

type LintDiagnostic = {
  severity: "error" | "warning" | "info";
  message: string;
  line?: number;
  column?: number;
  source: "cnes-lint";
  raw?: string;
};

Workbench UI

Controls

Add Lint beside Run. Lint has idle, linting, clean, warnings, and errors states. Run and Lint are separate commands because solve output and diagnostic output answer different questions.

Markers

Monaco markers are line-level for Packet 008A. The side panel remains the source of truth for diagnostics that cannot be attached to a line.

Panel

The diagnostics panel should stay quiet when clean. When errors exist, it should show count, severity, line, and message without covering the editor.

No Red Noise

Packet 008A should not create squiggles while the user is halfway through typing. Diagnostics appear because the user clicked Lint.

Acceptance Criteria

  • Workbench has a Lint action beside Run.
  • Lint executes current Monaco buffer with ["/work/input.cnes", "--lint", "--json"].
  • Diagnostics panel shows normalized messages.
  • Line-level Monaco markers appear only for diagnostics with real line data.
  • Run behavior, raw output, JSON download, and Tools runtime status remain covered; parent in-app browser smoke passed while scripted DevTools smoke remains externally blocked.

Success Metrics

  • A new Git remote is configured and visible in git remote -v.
  • The current committed repo state is pushed to the new origin.
  • Vercel is linked to that origin and automatically deploys pushes.
  • Vercel project root is Web Version, build command is npm run build, output directory is dist.
  • A public test URL is available for the human reviewer.
  • The public URL loads the React runner and fetches /runtime/cnes-worker.js, /runtime/cnes-module.wasm, and /runtime-data successfully.
  • The deployed public URL can run valid .cnes files and the invalid parser smoke without a backend.

Potential Roadblocks Without Human Present

Roadblock Impact Fallback While Human Is Away
No GitHub/Git remote URL provided Cannot set the correct new origin or push for automatic deployments. Prepare all deploy config locally and report the exact git remote add origin ... step needed.
No permission to create or push the remote repository Vercel cannot auto-update from the intended source. Use local Vercel preview deploy if authenticated; otherwise stop with a credential/permission note.
Vercel CLI not authenticated or wrong team selected Cannot link or deploy to the correct Vercel project. Run read-only status checks and record the needed login/team/project decision.
GitHub-Vercel integration missing Manual CLI deploy may work, but push-triggered preview deployments will not. Generate CLI preview URL and document that automatic deploy linkage needs human account authorization.
Repository scope ambiguity CoNES/ is currently untracked locally; a pushed repo may contain only the Web Version artifacts and docs. Do not stage CoNES/ without approval. Confirm whether deployment origin should include source engine history or only Web Version runtime artifacts.
WASM or worker MIME/path issue on Vercel Preview loads but solver fails at runtime. Add a small static-route verification and inspect deployed asset headers before changing runtime code.

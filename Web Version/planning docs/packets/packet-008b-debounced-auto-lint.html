Packet 008B

Debounced Auto Lint

Packet 008B turns the reviewed Packet 008A manual lint contract into a quiet automatic feedback loop after 008A is implemented and accepted. Auto lint runs after the user pauses, ignores stale results, and never blocks typing.

Implemented locally Reuses 008A path Uses lintSource Debounced Line-level markers Stale-safe Browser smoke added No solve coupling

Position

Opinionated Decision

Auto lint is allowed only after Packet 008A's manual lint path is implemented, verified, and human accepted. The auto loop must feel helpful and quiet: no linting on every keystroke, no blocking the editor, and no flashing stale diagnostics while the user is still typing.

User Outcome

A user edits CoNES source and receives diagnostics after a short pause, while still keeping explicit Run and Lint controls available.

Dependency

Implemented after 008A path

Packet 008B consumes the same manual lint API, normalized diagnostics, line-level Monaco marker path, and smoke coverage created for Packet 008A. It does not add a second diagnostic contract.

Inherited Contract

Manual API Only

Auto lint calls the same client.lintSource({ fileName, contents, lastModified }) path created by Packet 008A. It does not add a second worker mode, second diagnostics adapter, or UI-supplied argv.

Fixed Lint Arguments

The worker lint path remains fixed at ["/work/input.cnes", "--lint", "--json"]. Solve remains fixed at ["/work/input.cnes", "--json"].

Marker Precision

Auto lint uses the same line-level Monaco markers as 008A. It must not claim column accuracy or invent columns from parser text.

Raw Output

Raw lint stdout/stderr remains inspectable through the existing raw output affordance. Automatic diagnostics are a view over lint output, not a replacement for it.

Mechanics

Mechanic Required Behavior Why
Debounce Run lint 800-1200ms after the latest edit. Prevents noisy linting while the user is mid-expression.
Stale result guard Attach a source revision or request token to each lint request and ignore older responses. Prevents old diagnostics from overwriting newer source state.
Runtime readiness Auto lint only when runtime prewarm is ready, Packet 008A lint is available, and source is non-empty. Prevents automatic work from competing with initial runtime loading.
Manual override The Lint button remains available and runs immediately. Users need explicit control even when auto lint exists.
Run separation Run does not trigger auto lint and auto lint does not mutate solve state. Solve and diagnostics are different workflows.

State Model

Lint State

type AutoLintState =
  | "off"
  | "waiting"
  | "linting"
  | "clean"
  | "warnings"
  | "errors"
  | "stale"
  | "failed";

Source Revision

Every source edit increments a revision. Lint results apply only if their revision matches the current source revision when the response returns.

UI Rules

Quiet By Default

Auto lint status should be small. Use compact labels such as Waiting, Linting, Clean, or 3 errors. Do not add a second large status banner.

No Flicker

Existing diagnostics can remain visible while a new lint request is waiting. Replace them only when the current revision returns.

Typing Wins

If lint work makes Monaco feel slow, the implementation is wrong. Auto lint must yield to editing.

Failure Handling

If lint itself fails, show a small lint-failed state and preserve raw diagnostics. Do not block Run, clear Results, or make a lint failure look like a failed solve.

Verification

Browser Smoke

Browser smoke now edits source rapidly, waits for debounce, verifies the latest clean source wins, then clicks Run to confirm solve behavior remains independent. Parent in-app browser smoke passed for clean auto-lint staying clean through Run. The scripted verify:browser command still needs Chrome DevTools listening on 127.0.0.1:9223.

Inherited 008A Cases

Keep the 008A valid lint, parser-invalid lint, missing include lint, line-level marker, raw output, and solve matrix cases passing after auto lint is enabled.

Acceptance Criteria

  • Auto lint waits for a pause instead of running per keystroke.
  • Auto lint uses the Packet 008A lintSource path and fixed --lint --json argv.
  • Stale lint responses cannot overwrite current diagnostics.
  • Markers remain line-level and never invent column precision.
  • Manual Lint remains available.
  • Monaco editing remains responsive by debouncing and avoiding lint while Run is active.
  • Run remains separate and passes build/runtime plus parent in-app browser checks; scripted browser smoke awaits a DevTools-enabled Chrome session.
